**Goal:** complete metadata, structured data, sitemaps, `llms.txt`, OG images, and Lighthouse ≥ 95 in all categories on mobile, checked by a manual Lighthouse run (no Lighthouse CI, ADR-012 brochure scope).
**Read first:** `docs/SEO.md` (all), `.cursor/rules/seo.mdc`, `docs/ARCHITECTURE.md` §6.5–6.6.

### T10.1 — `buildMetadata` complete
**Steps:** Extend T07.6: per-type rules from SEO.md (articles: `article:published_time`, author; services: description fallback from teaser), OG image chain (seo.ogImage → hero/cover → build-time fallback), Twitter card `summary_large_image`, `icons`/manifest (`app/manifest.ts` with localized name: use the default locale), `verification` (Google/Bing from settings), `formatDetection: { telephone: false }` (we render tel links ourselves), `alternates.types` none. Ensure titles ≤ 60 and descriptions ≤ 160 chars (warn in Studio via validation, truncate safely in code).
**AC:** Unit tests per route type; Studio warns on overlong SEO fields.
**Done check:** `pnpm test src/lib/seo`.

### T10.2 — JSON-LD builders
**Steps:** `src/lib/seo/jsonld/*` with `schema-dts` types: `organization` (Dentist/MedicalBusiness with NAP, geo, openingHoursSpecification incl. special hours, `areaServed`, `sameAs`, `priceRange` only if real), `website`, `webPage`/`MedicalWebPage` (with `about`, `audience` (PeopleAudience/`suggestedMaxAge` for pediatric pages where appropriate, verify in schema.org)), `breadcrumbList`, `faqPage` (from the FAQ section), `article`/`BlogPosting` (author as `Person` linked to the team member, `reviewedBy` optional), `service`/`MedicalProcedure` where appropriate, `person` for team members (`jobTitle`, `worksFor`, `alumniOf` optional). Assemble a single `@graph` per page with stable `@id`s (`${siteUrl}#organization`). `JsonLd` component escapes `<` (`\u003c`). Stega off.
**AC:** Tests snapshot each builder; Google Rich Results Test and the Schema.org validator pass for home, a service, an article, the FAQ page (record URLs + results in PROGRESS).
**Done check:** `pnpm test src/lib/seo/jsonld` + manual validator runs on preview.

### T10.3 — Sitemap, robots, llms.txt
**Steps:** `app/sitemap.ts` from `getSitemapEntries()` with `alternates.languages` per entry (hreflang in the sitemap), `lastModified` from `_updatedAt`. If entries could exceed ~45k (never for these sites), use `generateSitemaps`; not needed. `app/robots.ts`: production allows all and points to the sitemap. Non-production disallows all. `/admin` and `/api` are always disallowed, and `/styleguide` too. AI crawlers are allowed by default (configurable list in `src/config/site.ts` so a client can opt out: `GPTBot`, `ClaudeBot`, `PerplexityBot`, `Google-Extended`, `CCBot`). `app/llms.txt/route.ts` per SEO.md §4 (force-static, regenerated by each publish-triggered build).
**AC:** Valid XML (test parses it); robots varies by env; `llms.txt` lists key pages in both languages with one-line descriptions.
**Done check:** `curl` the three files on preview; unit tests.

### T10.4 — OG images
**Steps:** Per SEO.md: CMS pages use the Sanity CDN crop (1200×630, `fit=crop`, hotspot). The fallback is `app/[locale]/opengraph-image.tsx` rendered **at build time** (static, `generateStaticParams` for locales) with `next/og`, brand colors from tokens (hardcode-free: read a JSON export of the primary tokens), and the wordmark in a Cyrillic-capable TTF from `public/fonts/` (loaded via `fs`/import at build). Never generate OG per request at runtime (CPU budget).
**AC:** The OG image renders Bulgarian text correctly; there are no runtime `ImageResponse` calls in the worker (verify via the build output: route is static).
**Done check:** open the generated images; check with a share debugger (e.g. opengraph.xyz) on preview.

### T10.5 — Performance pass and redirects
**Steps**
1. Audit with the `next-bundle-optimizer` skill + `@next/bundle-analyzer`: client JS on the home page ≤ budget in SEO.md §8, no Sanity/Studio code in site bundles, Motion lazy features only, `lucide-react` tree-shaken, images sized (`sizes`) and `priority` only on LCP.
2. Manual Lighthouse run (Chrome DevTools or PageSpeed Insights, mobile) on the preview URL for `/bg`, `/en`, a service, an article and contact, against the SEO.md §8 lab budgets (Perf ≥ 95, A11y 100, BP ≥ 95, SEO 100, LCP ≤ 1.8 s, CLS ≤ 0.02, TBT ≤ 150 ms, first-load JS ≤ 110 KB gzip, page weight ≤ 900 KB). No Lighthouse CI (ADR-012, brochure scope).
3. Redirects: `next.config.ts` `redirects()` from a `src/config/redirects.ts` list (for migrations from the client's old site: old URLs → new, 308), plus `www` ↔ apex handled at the Cloudflare level (document in NEW-CLIENT). Trailing slash policy consistent.
4. Fix everything below target and record the before/after in PROGRESS.
**AC:** The manual Lighthouse run meets the budgets on preview for all 5 URLs; no Sanity package in the client bundle for public routes; the redirects list works (308).
**Done check:** before/after scores per URL in PROGRESS.
