# SEO, AEO and Core Web Vitals

Goal: every client site is technically flawless, locally discoverable, and easy for AI answer engines to quote correctly.

## 1. Metadata (`src/lib/seo/buildMetadata.ts`)
Every route exports `generateMetadata` that calls `buildMetadata({ locale, doc, path, alternates })`. Never hand-roll metadata in pages.
- **title:** `seo.title || doc.title`, rendered through `siteSettings.seoDefaults.titleTemplate` (`%s · Brand`). The home page uses `brandName · tagline`. Root layout: `title: { template, default }`.
- **description:** `seo.description || doc.excerpt/intro || settings default`. 70–160 chars.
- **canonical:** absolute `NEXT_PUBLIC_SITE_URL` + localized path (via next-intl `getPathname`). No query strings. Pagination pages are self-canonical.
- **alternates.languages:** one entry per *existing* translation (`hreflang` from `localeMeta`), plus `x-default` → the default-locale URL. Generated from the same alternates data as the language switcher.
- **openGraph:** `type` (`website` / `article`), `locale` (`bg_BG`), `alternateLocale`, `siteName`, `url`, `images` (1200×630, see §5). Articles add `publishedTime`, `modifiedTime`, `authors`.
- **twitter:** `card: 'summary_large_image'`.
- **robots:** `noindex, nofollow` when `seo.noIndex`, on `/styleguide`, on all pages when `NEXT_PUBLIC_ENV !== 'production'`, and in draft mode.
- **metadataBase:** `new URL(NEXT_PUBLIC_SITE_URL)`.
- **Icons/manifest:** `app/[locale]/icon.png`, `apple-icon.png`, `manifest.ts` (name from settings; theme color from tokens).
- Always fetch with `stega: false` inside `generateMetadata`.

## 2. Structured data (JSON-LD) (`src/lib/seo/jsonld/*`, typed with `schema-dts`)
Render with `<JsonLd data={…} />`: `<script type="application/ld+json">` with `JSON.stringify(data).replace(/</g, '\\u003c')`. Use one `@graph` per page with stable `@id`s (`${siteUrl}/#organization`, `#website`, `${url}#webpage`).

| Builder | Where | Key properties |
| --- | --- | --- |
| `organization()` → `@type` from `siteSettings.businessType` (e.g. `Dentist`, a subtype of LocalBusiness/MedicalBusiness) | every page (in layout) | `name`, `url`, `logo`, `image`, `telephone`, `email`, `address` (PostalAddress), `geo`, `openingHoursSpecification`, `specialOpeningHoursSpecification`, `priceRange`, `areaServed`, `sameAs` (socials, GBP), `hasMap`, `employee`/`member` → Person `@id`s, `availableLanguage` (from locales), `currenciesAccepted: EUR` |
| `website()` | every page | `name`, `url`, `inLanguage` |
| `webPage()` (articles: `MedicalWebPage` for health clients when `businessType` is medical) | every page | `url`, `name`, `inLanguage`, `isPartOf`, `breadcrumb`, `lastReviewed`, `reviewedBy` (health articles) |
| `breadcrumbList()` | all non-home pages | positions from route hierarchy, localized names |
| `person()` | team section/about page | `name`, `jobTitle`, `image`, `worksFor`, `knowsAbout` (specialties), `sameAs`, `honorificPrefix` |
| `service()` | services page / service detail | `name`, `description`, `provider` → org `@id`, `areaServed`, `serviceType`; (future) `offers` |
| `faqPage()` | pages with an FAQ section (`emitSchema`) | `mainEntity: Question/acceptedAnswer` (plain text from Portable Text) |
| `blogPosting()` | article page | `headline`, `description`, `image`, `datePublished`, `dateModified`, `author` (Person), `publisher` (org), `inLanguage`, `mainEntityOfPage` |

Notes
- Google shows FAQ rich results only for a limited set of authoritative sites. Emit FAQPage anyway (AEO value, valid markup) but don't promise rich results.
- Rules: no markup for content not visible on the page, no fake reviews/ratings, no `aggregateRating` from self-collected testimonials.
- Unit tests: snapshot + schema shape checks for every builder. At launch, validate with the Rich Results Test + Schema Markup Validator.

## 3. Sitemap and robots
- `app/sitemap.ts`: all indexable URLs for all locales from `getAllRoutesForSitemap()` (stega off). Each entry has `lastModified` (`_updatedAt`) and `alternates.languages` (hreflang map). Exclude: noIndex docs, styleguide, legal pages marked hidden, pagination beyond page 1 (optional), draft-only docs. If more than 50k URLs (unlikely), use `generateSitemaps`.
- `app/robots.ts`: production → allow all, disallow `/admin`, `/api`, `/*/styleguide`, `sitemap: ${siteUrl}/sitemap.xml`. Non-production → `disallow: /`.
- Default behaviour: don't block AI crawlers in robots (AEO). Make it a config list in `src/config/site.ts` (`blockedBots: []`) so a client can opt out. Mention it in the privacy/terms discussion.

## 4. llms.txt (`app/llms.txt/route.ts`)
Generated at build (`dynamic = 'force-static'`, regenerated by every publish-triggered build), plain text, following the llmstxt.org convention:
```
# {brandName}
> {tagline}. {one-sentence description: who, what, where}.

Address: … · Phone: … · Hours: … · Languages: Bulgarian, English

## Services
- [Service name](url): teaser
## Team
- Dr. Name, role, specialties
## Key pages
- [Contact](url) · [First visit FAQ](url) · [Prices](url)
## Articles
- [Title](url): excerpt
```
One file per site, with the default-locale content first and EN links under `## English`. This is not an official standard, but it is low cost.

## 5. Open Graph images
- Priority: `seo.ogImage` → hero/cover image → `siteSettings.seoDefaults.ogImage` → build-time generated fallback.
- CMS images: Sanity CDN URL with `w=1200&h=630&fit=crop&crop=focalpoint` (hotspot) and `auto=format`. No Worker CPU.
- Generated fallback: `app/[locale]/opengraph-image.tsx` and `blog/[slug]/opengraph-image.tsx` with `next/og` `ImageResponse`, **statically generated at build** (`generateStaticParams`). It must load a Cyrillic-capable TTF from `public/fonts/` (the default OG font has no Cyrillic). Never generate OG per request on the Free plan.

## 6. Local SEO checklist (per client, in NEW-CLIENT.md)
- NAP identical everywhere: site footer, JSON-LD, Google Business Profile, Facebook, directories (BG: e.g. superdoc.bg, other doctor directories, Google/Apple Maps).
- Google Business Profile: correct category (e.g. "Pediatric dentist" / "Dentist"), hours incl. special hours, photos, services, website link with UTM (`?utm_source=gbp`), review request routine (offline).
- Bing Places, Apple Business Connect.
- Search Console + Bing Webmaster: verify the domain (DNS TXT), submit the sitemap, check hreflang errors after 2 weeks.
- Location pages are not needed for a single location. The home and contact pages carry the city name naturally («Детски зъболекар в Русе»).

## 7. AEO (answer engines) and content rules
- Each FAQ answer starts with a one-sentence direct answer, then details.
- Articles: answer-first intro (≤ 2 sentences), descriptive H2s phrased as questions where natural, a short "Key points" list, author + "medically reviewed by" + updated date (E-E-A-T for health/YMYL topics).
- Entity consistency: the same brand name, doctor names and titles everywhere. The `sameAs` links to official profiles.
- Text in HTML (not in images). Expandable tile content is server-rendered (see DESIGN-SYSTEM §9).
- Use plain, specific language («Приемаме деца от 2-годишна възраст»), not slogans.

## 8. Core Web Vitals and performance budgets
| Metric | Target (mobile, p75) | Lab budget (Lighthouse mobile) |
| --- | --- | --- |
| LCP | ≤ 2.0 s | ≤ 1.8 s |
| CLS | ≤ 0.05 | ≤ 0.02 |
| INP | ≤ 200 ms | TBT ≤ 150 ms |
| First-load JS (home) | — | ≤ 250 KB gzip (Next 16 App Router + next-intl; Perf and TBT are the real gates) |
| Total page weight (home) | — | ≤ 900 KB (first view) |
| Lighthouse | — | Perf ≥ 95, A11y 100, BP ≥ 95, SEO 100 |

Techniques (required)
- LCP: the hero image uses `priority` (preload) and `fetchPriority="high"`, has correct `sizes`, AVIF/WebP via the Sanity CDN, no entry animation, and the font has `display: swap` + an adjusted fallback.
- CLS: fixed header + spacer, `width`/`height` or `aspect-ratio` on all media, reserved space for the banner (it renders server-side, so no late insertion), Turnstile container with a fixed min-height, map placeholder with a fixed aspect ratio.
- INP: leaf client components only. No large hydration islands. Motion via LazyMotion. Event handlers do minimal work.
- Third parties: analytics script `defer`/`afterInteractive` (Umami/CF beacon ≈ 1–2 KB). Turnstile loads only when the form is near the viewport. Maps only on click. No Google Fonts requests (next/font self-hosts).
- Measurement: `useReportWebVitals` → `track('web_vital', …)` when the provider supports custom events (Umami). A manual Lighthouse run (mobile) on preview URLs against the budgets above (no Lighthouse CI, ADR-012). The `next-bundle-optimizer` skill audits JS.

## 9. Redirects and migrations
- If a client has an old site: crawl the old URLs (Screaming Frog or a sitemap) → a `redirects` list in `src/config/redirects.ts` → `next.config.ts` `redirects()` (308). Keep for ≥ 1 year.
- Trailing slash: none (`trailingSlash: false`). `www` vs apex: pick one, and 301 the other at Cloudflare (Redirect Rule).
